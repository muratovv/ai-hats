---
title: "Worktree для агентов: зачем каждому свой каталог"
---

Когда несколько агентов работают в одном репозитории, рано или поздно кто-то из них запускает тесты на чужих недоделанных правках.
Ветки этого не решают: ветка переключается в том же рабочем каталоге, и второй агент видит файлы первого.

Без изоляции агенты ломают друг другу сборку.
Один меняет сигнатуру функции, другой в этот момент гоняет тесты — и получает красный прогон по чужой вине, а потом полчаса ищет несуществующий баг у себя.

Git worktree даёт каждому агенту отдельный каталог на той же истории: `git worktree add ../wt-task-42 -b task-42`.
Это и есть главная мысль: изоляция агентов — это каталог, а не ветка.
Агент работает в своём дереве, коммитит в свою ветку, а слияние происходит только после ревью.

Таймаут сессии агента по умолчанию — 60 секунд, это задано в `config.example.yaml`; для длинных прогонов тестов его поднимают через `timeout`.

Иначе говоря, если у агентов нет своего дерева, они портят друг другу сборку: один правит код, второй тестирует то, что в этот момент лежит в каталоге, и падает на чужих изменениях.

Чтобы завести worktree на задачу, достаточно одной команды, а снести — `git worktree remove`.
Ветка при этом остаётся, и её можно слить или удалить отдельно.

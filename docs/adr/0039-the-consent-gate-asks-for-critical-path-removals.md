# ADR-0039: Об удалении критического пути спрашивает consent-гейт, а таймер харнесса выключается

## Статус

Принят (HATS-2044, 2026-09-28). Дополняет ADR-0031 [4]. Там гейт держит хук один, и
`permissions.*` вторым контуром не становится. Здесь хуку приходится держать
операцию, которую харнесс по-прежнему охраняет сам.

## Контекст

### Предохранитель харнесса

С версии 2.1.281 Claude Code считает `rm`/`rmdir` критического пути
предохранителем [1]. Критический путь — это корень, каталог верхнего уровня, домашний
каталог, рабочий каталог и его предки, а также цель, которую Claude Code не может
вычислить. Хук с `allow` такое удаление не одобряет никогда. В `auto` и
`bypassPermissions` терминальный вопрос идёт с двухминутным отсчётом и затем
отказывает. Headless `auto` отказывает сразу. Переменная
`CLAUDE_CODE_DISABLE_DANGEROUS_RM_TIMEOUT=1` отсчёт снимает. В `auto` удаление
тогда уходит классификатору.

Супервизор получил этот отсчёт в живой сессии: вопрос о `rm` ушёл в отказ, пока он
был занят другим. Headless-holder в `auto` такой вопрос не получает вообще.

### Замер

Фикстур [2], Claude Code 2.1.283, sonnet. Каждое плечо выполняет `rm -rf <cwd>` на
одноразовом каталоге, вердикт читается с диска.

| плечо | режим  | хук `ask` | переменная | терминал             | headless                                        |
| ----- | ------ | --------- | ---------- | -------------------- | ----------------------------------------------- |
| 1     | auto   | –         | –          | отсчёт, затем отказ  | `permission_denied` сразу, holder не спрошен    |
| 2     | auto   | ✔         | –          | **отсчёт всё равно** | **как 1: `ask` хука отброшен**                  |
| 3     | auto   | ✔         | ✔          | вопрос без срока     | `can_use_tool`, ждёт 150+ с; allow выполняет    |
| 4     | auto   | –         | ✔          | не мерили            | **выполнено классификатором, никто не спрошен** |
| 5     | bypass | ✔         | –          | отсчёт               | `can_use_tool`                                  |

Человека в `auto` ждёт только плечо 3: `ask` хука **и** переменная. Одна
переменная без хука даёт плечо 4 — удаление рабочего каталога, о котором никто не
спрошен. Текст вопроса в плече 3 принадлежит Claude Code (`safetyCheck`), а не хуку.

## Решения

### D1 — удаление критического пути — consent-операция `fs.remove`

Операция `fs.remove` с точкой `critical-path` записана в реестр операций [3] и
объявлена трейтом `trait-agent` под `apps.consent_gate`. Вопрос идёт той же дорогой,
что `rack.transition` и `wt.*`: `consent_requirement` → `present_question`. Журнал
при этом общий, и `consent` знает её имя.

Точка ловит **надмножество** списка Claude Code:

- каталог верхнего уровня;
- рабочий каталог и его предки, включая относительные написания;
- каталог на уровне или выше записи `additionalDirectories`;
- любой операнд с `$` или обратной кавычкой;
- неразбираемую строку со словом `rm`.

Промах здесь — это плечо 4, поэтому лишний вопрос дешевле. Сужение, если оно
понадобится, делается отдельной задачей. `/` и `~` по-прежнему отказываются жёстко,
раньше любого вопроса.

### D2 — операция только в хуке и без тикета

У `rm` нет обёртки на `PATH`: шим под каждым скриптом и под собственной оболочкой
человека обошёлся бы дороже, чем стоит. Поэтому погашать тикет некому, и `ask`
приходит без `updatedInput`, команда выполняется как написана. Чтобы такая
операция читала только свои бинари, в `OperationSpec` появляется поле `binaries`.
Без него операция с `surface=None` получала бы argv любого инструмента (argv
приходит без имени бинаря) и прочитала бы `rack transition X done` как удаление.

### D3 — операцию нельзя заглушить

Грант, `AI_HATS_CONSENT_ACK` и `AI_HATS_DESTRUCTIVE_ACK` вопрос не снимают. Для
остальных операций тишина гейта означает «пропустить». Здесь `allow` харнесс не
примет, поэтому тишина лишь передаёт команду классификатору. Поле
`OperationSpec.grantable = False`: гейт не смотрит на гранты для такой операции,
`consent` отказывает в ней по имени и не включает её в `all`.

### D4 — переменная ставится только там, где стоит гейт

Claude surface выставляет `CLAUDE_CODE_DISABLE_DANGEROUS_RM_TIMEOUT=1` при двух
условиях сразу: композиция объявляет `fs.remove`, и `safety_gate.py` материализован
как PreToolUse-хук. Этого достаточно для обычной сессии, headless и automate: все
три получают `plan.env`. Голый `claude` (например, `session retro --interactive`),
роль без объявления и сессия с выключенными хуками переменную не получают. Там
остаётся отсчёт Claude Code, а он отказывает безопасно.

### D5 — один режим политики

Отдельной ветки для `bypassPermissions` нет, переменная ставится в любом режиме.
Решение супервизора: политика одна.

## Следствия

- В терминале и в headless вопрос об удалении критического пути ждёт человека, а не
  истекает.
- Остаются три дыры, где при включённой переменной классификатор решает молча:
  - гейт упал в fail-open (в том числе при нечитаемом объявлении consent);
  - `AI_HATS_YOLO=1`;
  - каталог, добавленный на ходу через `/add-dir`: в файлах настроек его нет.

  Каждая из них — это решение не спрашивать, принятое заранее или записанное в журнал.
- Claude Code может расширить свой список быстрее, чем гейт. Утверждение D1 про
  надмножество относится к **чужому** релизу. Фикстур [2] перезапускается руками,
  CI удержать его не может.
- `permissions.ask` на `fs.remove` запрещён по ADR-0031 D2, как на любую
  gated-операцию.

## Не входит в решение

- Сужение правила `$`-операндов.
- Другие разрушающие инструменты (`find -delete`, `git clean`): предохранитель
  харнесса их не касается.
- Другие surface (codex, agy, cline). Объявление к ним доходит, но предохранителя
  Claude Code там нет, а переменная относится только к claude.
- Замена текста вопроса Claude Code нашим.
